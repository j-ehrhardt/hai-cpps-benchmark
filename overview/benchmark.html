Benchmark

The goal of HAI-CPPS is to provide a comprehensive benchmark for evaluating machine-learning algorithms along two axes:

  • CPPS complexity

  • Fault complexity

HAI-CPPS includes ten different datasets, each recorded from a unique process-plant setup. Every release provides discrete, continuous, and hybrid measurement views. The associated oracle states and metadata are separate offline artifacts; they are not online features.

You can find the release structure and loader example here.

CPPS Complexity

HAI-CPPS features ten different process-plant configurations, each exhibiting increasing structural and behavioral complexity.

Fault Complexity

For every enabled module fault proxy, the campaign generator creates a dedicated one-fault scenario and validates it against its matching normal run. This enables systematic evaluation across fault types without multi-fault confounding.

Measurement Views and Offline Artifacts

The v2 release distinguishes between online measurement views and offline artifacts:

  • continuous: real-valued process measurements;

  • discrete: binary and discrete control or sensor values;

  • hybrid: a combination of continuous and discrete measurement features;

  • oracle states: simulator-derived internal states for offline evaluation, stored separately from measurements; and

  • metadata: fault events, system knowledge, technical timing, validation, and provenance stored in separate files.

Use only the chosen measurement view as an online model input. The provided loader removes scenario and time identifiers through its online_features property and exposes oracle information only by explicit opt-in.
