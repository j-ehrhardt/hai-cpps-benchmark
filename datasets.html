Datasets

The HAI-CPPS v2 benchmark consists of ten datasets with increasing system complexity.

Each generated scenario contains three measurement views:

  • continuous: real-valued process measurements;

  • discrete: binary and discrete control or sensor values; and

  • hybrid: the combination of continuous and discrete measurement features.

The measurement views are release feature tables. Simulator-derived states are kept separately in oracle_states.parquet and are intended only for offline analysis or evaluation. They are never automatically merged into a measurement table.

Every scenario release has the following layout:

<scenario-id>/
├── continuous/measurements.parquet
├── discrete/measurements.parquet
├── hybrid/measurements.parquet
├── oracle_states.parquet
├── fault_events.json
├── system_knowledge.yaml
├── technical_timing.json
├── sim_setup.json
├── provenance.json
├── validation.json
└── audit/internal_verification.csv

fault_events.json describes the normal or one-fault-at-a-time scenario and its fault window. system_knowledge.yaml provides structural and component metadata. technical_timing.json describes sampling, event alignment, and timing details. The validation and provenance files record the checks and runtime context used to produce the release.

To load a release without mixing oracle information into model inputs, use the supplied loader from the repository’s code directory:

from pathlib import Path

from dataset_io import load_scenario_dataset

online = load_scenario_dataset(
    Path("/path/to/scenario"), measurement_view="hybrid"
)
X = online.online_features

# Explicit opt-in for offline analysis; oracle remains a separate table.
offline = load_scenario_dataset(
    Path("/path/to/scenario"),
    measurement_view="hybrid",
    include_oracle=True,
)
oracle = offline.oracle_states
