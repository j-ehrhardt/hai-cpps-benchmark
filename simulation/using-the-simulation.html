Using the Simulation

You can use the HAI-CPPS v2 code and models to recreate the benchmark or to generate a validated custom topology. The supported entry point is code/sim.py.

Note:
If you want to use the models in Simulink, you can export FMU models from OMEdit and import them into Simulink.

Replicate the Benchmark Datasets

With the project environment activated and omc available on PATH, validate the configuration:

python code/sim.py validate --config code/benchmark_setup.json

Generate the complete v2 campaign with:

python code/sim.py run \
  --config code/benchmark_setup.json \
  --campaign full \
  --output output/v2 \
  --build-root work/v2 \
  --seed 20260831

full generates the ten normal scenarios and all 110 enabled one-fault scenarios in the supplied configuration. A run stops with an error if the simulator result, export bundle, or normal/fault validation is invalid.

To run only one normal scenario, use --campaign normal --scenario ds1. To execute a particular normal/fault pair, specify the target module and fault:

python code/sim.py run \
  --config code/benchmark_setup.json \
  --scenario ds1 \
  --module mixer0 \
  --fault anom_pump50 \
  --output output/smoke \
  --build-root work/smoke \
  --seed 20260831

Existing scenario releases are protected. Use --resume to reuse only complete, compatible releases; use --force to intentionally regenerate a selected scenario. The two options cannot be combined.

Parallel execution

Run different base topologies in parallel and give every process a distinct output and build root:

parallel -j 4 --line-buffer --halt soon,fail=1 \
  'python code/sim.py run \
    --config code/benchmark_setup.json \
    --campaign full \
    --scenario {} \
    --output output/{} \
    --build-root work/{} \
    --seed 20260831' \
  ::: ds1 ds2 ds3 ds4 ds5 ds6 ds7 ds8 ds9 ds10

Adjust -j 4 to the number of simulations the host can sustain. Do not share a build root between concurrent simulations.

⚠️ Warning:
Complete campaigns take time. Start with a normal scenario or one explicit normal/fault pair to verify the local installation.

Create Your Own Simulation

To create a custom CPPS configuration, use code/benchmark_setup.json as a template. It defines modules, connections, enabled fault proxies, and simulation timing. Keep model-file paths relative to the configuration file.

Validate a custom configuration before running it:

python code/sim.py validate --config /path/to/benchmark_setup.json
python code/sim.py run \
  --config /path/to/benchmark_setup.json \
  --campaign full \
  --output output/custom \
  --build-root work/custom \
  --seed 20260831

The validator checks the JSON schema, module types, port connectivity, supported fault names, mutually exclusive fault pairs, timing, and referenced model files. The export workflow does not modify the checked-in simulation models or calls.
